## Backend-Native Initialization Policy

Operational KODAMA analyses must use a PCA initialization generated by the
same backend selected for that analysis:

```text
CPU   -> CPU PCA initialization
CUDA  -> CUDA PCA initialization
Metal -> Metal PCA initialization
```

`KODAMA.matrix(..., visual.init=TRUE)` stores the correct initialization in
`fit$visual_init`. Pass that backend-specific object to visualization. The
standalone R wrapper currently exposes CPU and CUDA UMAP/openTSNE; Metal
KODAMA results retain their Metal PCA initialization when passed to a
supported visualization backend.

```r
fit <- KODAMA.matrix(
  data,
  M = 100L,
  Tcycle = 100L,
  ncomp = 50L,
  landmarks = 100000L,
  splitting = 100L,
  graph.neighbors = 100L,
  knn.k = 50L,
  classifier = "pls_lda",
  backend = backend,
  seed = 1234L,
  visual.init = TRUE
)

stopifnot(fit$visual_init$backend == backend)

layout <- KODAMA.visualization(
  fit,
  method = "UMAP",
  init = fit$visual_init$umap,
  k = 30L,
  backend = if (backend == "metal") "cpu" else backend,
  n.cores = 4L,
  n.epochs = 200L,
  graph.mode = "fuzzy",
  seed = 4L
)
```

Do not pass a CPU PCA initialization to a CUDA or Metal visualization.

## Historical UMAP Diagnostic

The July 20 figure used:

```text
k:                 30
n.epochs:          200
UMAP seed:         4
UMAP backend:      cpu for classic, CPU-core KODAMA, and CUDA-core KODAMA
initialization:     the same original-data PCA initialization from the CPU result
color/evaluation:  MetRef truth labels
```

Truth labels were not supplied to KODAMA and were not used to initialize UMAP.
They were used only for plot colors and post hoc metrics.

That figure deliberately reused CPU initialization and CPU UMAP to isolate
the KODAMA core backend. It is a historical parity diagnostic, not the
operational initialization policy. Reproducing that particular image and
running a correct backend-native analysis are different tasks.

## Why the 20260725 Smoke Run Differs

| Item | Accepted reference | Smoke run |
|---|---:|---:|
| Core revision | `ca11c009` | image label `cd691398` |
| Dataset | `MetRef_float32.RData` | `MetRef.RData` |
| M | 100 | 10 |
| Tcycle | 100 | 10 |
| Requested landmarks | 100000 | 873 |
| Effective landmarks | 655 | 655 |
| Core `knn.k` | 50 | 30 |
| Core seed | 1234 | 4 |
| Visualization policy | shared CPU historical diagnostic | backend-specific PCA and renderer |
| UMAP implementation | host `kodamaR`, built July 7 | July 24 container |
| Reported quality | truth silhouette, CV, ARI | embedding kNN accuracy and silhouette |

The two dataset files contain the same labels and nearly the same values, but
they are not bitwise identical. The maximum matrix difference after conversion
to double is about `9.41e-7`. Use the float32 file for exact provenance.

The dominant errors are the old core revision and the 100-fold reductions in
the M-by-Tcycle optimization budget. Dataset quantization is secondary.

The smoke run's backend-specific PCA initialization and backend-matched
renderer are correct. They should not be changed to shared CPU initialization.

The renderer change is independently material:

| Core objects | Renderer | CPU truth silhouette | CUDA truth silhouette |
|---|---|---:|---:|
| accepted M100/T100 | July 7 host `kodamaR` | 0.830293 | 0.844147 |
| accepted M100/T100 | July 24 container, `graph.mode="fuzzy"` | 0.798260 | 0.807719 |
| accepted M100/T100 | July 24 container | 0.527442 | 0.525612 |
| smoke M10/T10 | July 7 host `kodamaR` | 0.676788 | 0.590591 |
| smoke M10/T10 | July 24 container, `graph.mode="fuzzy"` | 0.673102 | 0.600155 |
| smoke M10/T10 | July 24 container | 0.397664 | 0.404773 |

Thus neither replacing only the core parameters nor replacing only the
renderer is enough.

The current `KODAMA.visualization()` API added
`graph.mode = c("binary", "fuzzy")`. Because `match.arg()` selects the first
choice, omitting this argument silently uses `"binary"`. The accepted
renderer predates this argument. With the current package, explicitly use:

```r
KODAMA.visualization(
  fit,
  method = "UMAP",
  init = fit$visual_init$umap,
  k = 30L,
  backend = fit$backend,
  n.cores = 4L,
  n.epochs = 200L,
  graph.mode = "fuzzy",
  seed = 4L
)
```

This recovers most, but not all, of the accepted quality. Strict reproduction
still requires the archived July 7 renderer.

retained. Each output records and validates both backends.
